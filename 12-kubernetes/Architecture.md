## 1. Kubernetes Ճարտարապետություն (Architecture)

Kubernetes cluster-ը բաժանվում է երկու հիմնական մասի՝ **Control Plane** (մեխանիզմի "ուղեղը") և **Worker Nodes** (որտեղ աշխատում են ծրագրերը)։

```text
 ┌─────────────────────────────────────────────────────────────────────────┐
 │                              CONTROL PLANE                              │
 │                                                                         │
 │   ┌───────────────┐      ┌─────────────────┐      ┌─────────────────┐   │
 │   │  API Server   │ ──── │      etcd       │      │   Scheduler     │   │
 │   └───────┬───────┘      └─────────────────┘      └─────────────────┘   │
 │           │                                                             │
 │           └───────────────────────────────┐                             │
 │                                           ▼                             │
 │                               ┌──────────────────────┐                  │
 │                               │ Controller Manager   │                  │
 │                               └──────────────────────┘                  │
 └───────────────────────────────────┬─────────────────────────────────────┘
                                     │
           ┌─────────────────────────┴─────────────────────────┐
           ▼                                                   ▼
 ┌───────────────────────────┐                       ┌───────────────────────────┐
 │       WORKER NODE 1       │                       │       WORKER NODE 2       │
 │ ┌─────────┐   ┌─────────┐ │                       │ ┌─────────┐   ┌─────────┐ │
 │ │ Kubelet │   │ Kube-   │ │                       │ │ Kubelet │   │ Kube-   │ │
 │ │         │   │ Proxy   │ │                       │ │         │   │ Proxy   │ │
 │ └────┬────┘   └─────────┘ │                       │ └────┬────┘   └─────────┘ │
 │      │                    │                       │      │                    │
 │ ┌────▼──────────────────┐ │                       │ ┌────▼──────────────────┐ │
 │ │ Container Runtime     │ │                       │ │ Container Runtime     │ │
 │ │ (Containerd/Docker)   │ │                       │ │ (Containerd/Docker)   │ │
 │ └─────────┬─────────────┘ │                       │ └─────────┬─────────────┘ │
 │           │               │                       │           │               │
 │ ┌─────────▼─────────────┐ │                       │ ┌─────────▼─────────────┐ │
 │ │   Pod A   │   Pod B   │ │                       │ │   Pod C   │   Pod D   │ │
 │ └───────────────────────┘ │                       │ └───────────────────────┘ │
 └───────────────────────────┘                       └───────────────────────────┘
```

### Control Plane (Master Node) Components

1. **kube-apiserver**
   - **Ինչ է անում:** Cluster-ի կենտրոնական դարպասն է (REST API)։ Բոլոր հրամանները (`kubectl`, Dashboard, ներքին components) անցնում են սրա միջով։
   - **Ինչպես է աշխատում:** Վավերացնում (Authentication/Authorization) և ստուգում է YAML հարցումները, ապա տվյալները գրանցում `etcd`-ում։

2. **etcd**
   - **Ինչ է անում:** Key-Value տվյալների բազա է, որտեղ պահվում է Cluster-ի ամբողջ վիճակը (state)։
   - **Կարևոր է:** `etcd`-ն Single Source of Truth է։ Եթե այն վնասվի առանց backup-ի, cluster-ը կկորչի։

3. **kube-scheduler**
   - **Ինչ է անում:** Որոշում է, թե նոր ստեղծված Pod-ը **որ Worker Node-ի վրա** պետք է տեղադրվի։
   - **Ինչպես է որոշում:** Հաշվի է առնում Node-ի ռեսուրսները (CPU/RAM requests), Taints/Tolerations, Affinity/Anti-affinity կանոնները։

4. **kube-controller-manager**
   - **Ինչ է անում:** Աշխատեցնում է background loop-եր (controllers), որոնք համեմատում են _Actual State_-ը (ընթացիկ վիճակը) _Desired State_-ի (ցանկալի վիճակի) հետ։
   - **Օրինակ:** Եթե 3 Pod-ից 1-ը սպանվի, ReplicaSet Controller-ը դա նկատում է և API Server-ին ասում է ստեղծել 1 նոր Pod։

### Worker Node Components

1. **kubelet**
   - **Ինչ է անում:** Ամեն node-ի վրա աշխատող «գործակալն» (agent) է։
   - **Աշխատանքը:** API Server-ից ստանում է հրամանը (օրինակ՝ «աշխատեցրու այս Pod-ը»), ապա հրահանգում է Container Runtime-ին run անել container-ը և վերահսկում է դրա health status-ը։

2. **kube-proxy**
   - **Ինչ է անում:** Node-ի վրա ցանցային կանոններն է ղեկավարում (Network proxy)։
   - **Աշխատանքը:** Փոփոխում է OS-ի IP tables-ը (`iptables` կամ `eBPF/cilium`)՝ ապահովելով traffic-ի ճիշտ routing-ը դեպի համապատասխան Pod-եր (Service IP -> Pod IP)։

3. **Container Runtime**
   - Software-ն է, որը ֆիզիկապես աշխատեցնում է container-ները (օրինակ՝ `containerd`, `CRI-O`)։
